# this-code-test-creator

## 実行フロー

1. 対象と期待動作を確認する
   - テスト対象の production ファイルを特定する
   - 期待動作・境界条件・既知の不具合・追加したいケースを確認する
   - 判断に必要な情報が不足している場合は、テストを追加せずユーザーへ確認する

2. プロジェクト規約を確認する
   - `README.md` と `AGENTS.md` を確認する
   - 既存テストの配置・命名・import・mock 方針を確認する
   - フレームワークは Vitest。プロジェクトは `cli`（`scripts/node/__test__/**/*.test.ts` / node 環境）と `frontend`（`src/**/*.{test,spec}.{ts,tsx}` / jsdom 環境）の 2 つ
   - Node タスクのテストは `scripts/node/__test__/<layer>/<name>.test.ts` に置き、対象と同じディレクトリ構成をミラーする
   - `frontend` プロジェクトはテスト未整備で、`setupFiles` の `src/test/setup.ts` も未作成。`src` 配下にテストを追加する場合は先に同ファイルを用意する

3. 既存実装と既存テストを確認する
   - 対象ファイルの参照元・既存テスト・関連 helper を確認する
   - テスト対象の公開された振る舞いを優先して把握する
   - 実装詳細に依存しすぎるテストは避ける

4. テスト方針を決める
   - テストファイルの配置は既存テストの規約に合わせる
   - UI コンポーネントテストは対象自身が生成する HTML・クラス・属性のみを検証する
   - 子コンポーネント・内部実装の詳細に依存するアサーションは書かない
   - mock は外部ライブラリ（`fs-extra` / `fast-glob` / `sharp` / `svgo` など）に限定し、プロジェクト内コードはモックせず実実行させる
   - モック定義後に `await import('@scripts-node/commands/...')` で対象を読み込む既存パターンに合わせる
   - import はエイリアス（`@scripts-node/*` / `@root/*` / `@/*`）で書く
   - `globals: true` だが、既存テストに合わせて `vitest` から `describe` / `it` / `expect` / `vi` を明示 import する
   - 分岐が多い helper / lib は境界値と異常系を含める

5. テストを実装する
   - 既存テストの書き方・命名・セットアップに合わせる
   - Arrange / Act / Assert が読み取りやすい構成にする
   - 実装詳細ではなく、入力と出力・表示・状態変化などの振る舞いを検証する
   - テスト追加のために production コード修正が必要な場合は、勝手に変更せず確認する

6. 検証する
   - `pnpm fix` → `pnpm check` → 対象テスト（`pnpm test:cli` または `pnpm test:frontend`）の順で進める
   - カバレッジまで確認する場合のみ `pnpm test` を使う
   - 失敗した場合は原因を特定し、テストまたは必要最小限の実装を修正して再検証する

7. `$this-code-reviewer` でレビューする
   - 追加・更新したテストファイルと関連 production ファイルを `$this-code-reviewer` でレビューする
   - 指摘がある場合は対応要否を判断し、必要なものは修正して再検証する

8. 結果を報告する
   - 追加・更新したテスト内容
   - 変更ファイル一覧
   - 実行した検証と結果
   - `$this-code-reviewer` のレビュー結果
   - 残課題（あれば）

## 入力解釈ルール

- 「テストを作って」: 対象ファイルに対応する新規テストを追加する
- 「テストケースを追加して」: 既存テストへ不足ケースを追加する
- 「このバグの再現テストを追加して」: 失敗条件を再現するテストを先に作る
- 実装修正が主目的なら `$this-code-modifier` を使う
- レビューのみが目的なら `$this-code-reviewer` を使い、原則として実装変更しない

## 出力フォーマット

- 要約（どの振る舞いをテストしたか）
- 変更ファイル一覧
- 実行した検証と結果
- `$this-code-reviewer` のレビュー結果
- 実行できなかった検証（必要時のみ）
- 確認事項（必要時のみ）
- 次アクション（必要時のみ）
